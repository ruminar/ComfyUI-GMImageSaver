# JPEGコメント処理仕様

- 決定日: 2026-08-21
- 対象: `GMImageJpegSave` の `comment` 入力
- 実装: `nodes.py`
- 退行テスト: `tests/test_nodes.py`

## 背景

GraphicsMagickへコメント本文をコマンドライン引数として直接渡すと、GraphicsMagick自身の引数長制限により長いプロンプトの保存が失敗する。また、Windowsのコマンドライン長、文字コード変換、先頭の `@` の解釈などにも影響される。

このため、コメント本文は長さにかかわらずUTF-8の一時ファイルを経由して渡す。

## 決定事項

### コメント未設定時

次の場合は一時ファイルを作成せず、GraphicsMagickへ `-comment` を渡さない。

- `comment` が未接続または `None`
- `comment` が空文字列
- 正規化後に有効な文字が残らない

### コメント設定時

有効なコメントが1文字以上ある場合は、短いコメントでも必ず一時ファイルを使用する。

- OS標準の一時ディレクトリに、バッチごとに1ファイル作成する
- 同じバッチ内の全画像で同じファイルを再利用する
- バイナリモードでUTF-8バイトを書き、BOMは付けない
- GraphicsMagickには `-comment @<一時ファイルの絶対パス>` として渡す
- 正常終了、GraphicsMagickのエラー、タイムアウト、OSエラーのいずれでも `finally` で削除を試みる
- 削除に失敗した場合は警告を出し、本来の保存結果や例外を隠さない

プロセスの強制終了やOS停止では `finally` が実行されず、一時ファイルが残る可能性がある。

## 文字の正規化

JPEGコメントへ渡す前に次の文字を除去する。

- BOM文字 `U+FEFF`
- NULを含む、タブ・LF・CR以外のC0制御文字
- DELおよびC1制御文字
- 不正なUnicodeサロゲート文字

次の文字は保持する。

- タブ `U+0009`
- LF `U+000A`
- CR `U+000D`
- 日本語、絵文字、アクセント付き文字などの正しいUnicode文字

## サイズ上限

- 正規化後にUTF-8へ変換し、最大65,000バイトとする
- 上限を超える場合は、UTF-8の文字境界を壊さない位置で末尾を切り詰める
- 切り詰め後も正しいUTF-8としてデコードできなければならない

## 改行

入力中のタブ、LF、CRは一時ファイルへそのまま書き込む。ただし、GraphicsMagickが `@ファイル` を読み込む際に改行をCRLFへ正規化し、末尾にもCRLFを追加する。行の区切りという意味は保持されるが、入力とJPEG内コメントのバイト列完全一致は保証しない。

## 退行防止条件

自動テストでは少なくとも次を保証する。

1. BOM、NUL、不要な制御文字を除去し、タブ・改行・日本語・絵文字を保持する
2. 65,000バイトを超えるUTF-8コメントを文字境界で安全に切り詰める
3. GraphicsMagickへコメント本文を直接渡さず、`@一時ファイル` を渡す
4. 1,026文字を超える長文コメントも一時ファイルへ完全に書き込む
5. コメント未設定時は一時ファイルを作成しない
6. GraphicsMagick実行中に例外が発生しても一時ファイルを削除する

実機確認では、日本語・絵文字を含む5,000文字超のコメントをGraphicsMagickでJPEGへ保存し、内容の保持と一時ファイルの削除を確認する。
